## 3. Architecture

1. Context clause (`resolved.context`): `library ieee;` `use ieee.std_logic_1164.all;` `library olo;` `library openwire;` `library openrmap;` `library openspp;`
2. Declare every signal of `resolved.signals` (one per port of an instance, named `<instance>_<port>_s`, with the type of the port).
3. Instantiate every entry of `resolved.instances` as `i_<id> : entity <library>.<entity>`: a generic map with every generic (the value is the VHDL literal in `vhdl`, package constants fully qualified; write the defaults too, where `default` is true, so that a new default of a core cannot change the system unnoticed), and a port map with the `actual` of every port. Leave out the ports with `useDefault` (they keep their VHDL `default`). Clocks and resets are port actuals on purpose: never assign a clock to another signal.
4. Write every entry of `resolved.nets` as a concurrent assignment `<to> <= <from>;`. They connect the interfaces signal by signal (a packed data word bit by bit), set the side band constants and tie-offs, and connect the top-level ports.

## 4. Clocks and resets

| Clock domain | Frequency | Clock | Reset generator |
| --- | --- | --- | --- |
| System clock (`sys`) | 100 MHz | top-level port `Clk_sys` | `auto_rst_sys` (olo_base_reset_gen, output `auto_rst_sys_RstOut_s`) |
| Link clock (`link`) | 200 MHz | top-level port `Clk_link` | none: no block of the domain has a synchronous reset |

Reset ports (`reset` of the port):

| Port | Reset | Actual | Why |
| --- | --- | --- | --- |
| `spw0.Rst` | asynchronous | `Rst` | Asynchronous reset; the core synchronises its release in every domain. |
| `rmap0.Rst` | synchronous | `auto_rst_sys_RstOut_s` | Synchronous reset in the clock domain System clock (clock Clk): the output of the reset generator auto_rst_sys. |

`Rst` is the asynchronous system reset. A reset generator asserts the reset of its domain at once and releases it synchronously to the clock; a block with an asynchronous reset synchronises the release itself.

## 5. Constraints

Every clock crossing is an Open Logic block. Between the clocks of a crossing a maximum delay applies in both directions, the period of the faster clock, data path only (Open Logic clock crossing principles). Do not declare these clocks as asynchronous clock groups: in Vivado `set_clock_groups -asynchronous` overrides the delay limits.

- False path through `spw0_Spw_DIn`, `spw0_Spw_SIn` (`set_false_path -through` in Vivado: valid whether the port is a device pin or a pin of the system inside a larger design): Inputs that spw0 synchronises itself.
- Output registers in the I/O blocks for `spw0_Spw_DOut`, `spw0_Spw_SOut`: Place the output flip-flops of data and strobe in the I/O blocks with matched routing.
- Maximum delay from the clock of `Clk_link` to the clock of `Clk_sys`: 5 ns, data path only (`set_max_delay -datapath_only` in Vivado). Clock crossings of spw0: the period of the faster clock.
- Maximum delay from the clock of `Clk_sys` to the clock of `Clk_link`: 5 ns, data path only (`set_max_delay -datapath_only` in Vivado). Clock crossings of spw0: the period of the faster clock.
- AMD Vivado: source the script of Open Logic once. It reads the scoped constraints of olo_base_cc_reset, olo_base_cc_bits, olo_base_cc_simple, olo_base_reset_gen and olo_base_ram_sdp wherever the system uses them, also inside the cores. tools/vivado/all_constraints_amd.tcl would also read those of olo_intf_sync, which expect device pins at its input and stop the build (ERROR 18-513) where a block synchronises internal signals with it, as ofb_pa_gty does; a block that synchronises device pins declares its own false path for them. File `src/base/tcl/olo_base_constraints_amd.tcl` of Open Logic.

## 8. Notes from the user guides

**SpaceWire port** (`owr_core`, `spw0`): https://openspacehdl.org/openwire/docs/user_guide.html

- LVDS output buffers for data and strobe and LVDS input buffers with fail-safe biasing belong to the top level; the core contains no I/O buffer.
- Enable the safe implementation of state machines in the synthesis tool.
- Set INT_HOLDOFF and INT_ACK_DELAY for the network before distributed interrupts are used.
- Serve the indication ports before the indication FIFO (16 entries) fills.
- Write registers as 32-bit words; a read that depends on a write waits for the write response.

**RMAP node** (`omap_core`, `rmap0`): https://openspacehdl.org/openrmap/docs/user_guide.html

- Rst is synchronous and high-active; synchronise its release to Clk, for example with olo_base_reset_gen.
- M_RepData, M_Conf and M_User must be served when connected; a stalled output stalls the received packet stream and the link.
- RMAP address bits above AxiAddrWidth_g must be zero in the windows.
- With AxiMaxBeats_g = 1 and AxiDataWidth_g = 32 the memory master issues single transfers only and can drive an AXI4-Lite slave; tie M_Axi_RLast to '1'.
- An access longer than one command of the memory master (2^(AxiAddrWidth_g - 2) - AxiDataWidth_g/8 bytes, at most 2^24 - AxiDataWidth_g/8) is split into several commands.

**N-Char adapter** (`spp_nchar`, `nchar0`): https://openspacehdl.org/openspp/docs/user_guide.html

- A received end of packet marker without data characters is discarded.
- A link packet that ends with a beat without valid bytes gets its marker after the bytes of the earlier beats; a link packet without any byte sends nothing.

**Space Packet node** (`spp_core`, `spp0`): https://openspacehdl.org/openspp/docs/user_guide.html

- Rst is synchronous and high-active; synchronise its release to Clk, for example with olo_base_reset_gen.
- After the reset the core initialises both APID tables (2048 clock cycles); packets are sent and delivered once the tables are ready.
- Serve every receive port, or place a buffer behind a port whose user can stall for long.
- TxBufferBytes_g holds the longest SDU of a port, RxBufferBytes_g the longest Space Packet.
- Hold the side band (TUser) of a send port constant during an SDU.
- A last beat without valid bytes (Keep all zero) ends an SDU or packet at the inputs; an SDU without any byte is rejected (0x02). The outputs never carry a beat without valid bytes.
- The user supplies the packet secondary header at the start of the Octet String and keeps the secondary header flag of an APID static.

## 11. Protection scope

The system is designed for radiation environments together with the triple modular redundancy (TMR) of the synthesis tool, like the Open Logic ft entities its blocks are built on (`resolved.protection`).

Blocks that protect their memories with SECDED ECC and report it in their registers (the channels count the double-error flags of the status register):

| Block | Channels | Status | Counters | Error injection | Evidence |
| --- | --- | --- | --- | --- | --- |
| `spw0` (`owr_core`) | 6 | `ECC_STATUS` (0x080) | `ECC_SELECT` (0x084), `ECC_COUNT` (0x088) | `ECC_INJECT` (0x08C) | user guide section 5 (protection scope) and the register map |
| `rmap0` (`omap_core`) | 3 | `ECC_STATUS` (0x0A0) | `ECC_SELECT` (0x0A4), `ECC_COUNT` (0x0A8) | `ECC_INJECT` (0x0AC) | user guide section 6 (protection scope) and the register map |
| `spp0` (`spp_core`) | 8 | `ECC_STATUS` (0x060) | `ECC_SELECT` (0x064), `ECC_COUNT` (0x068) | `ECC_INJECT` (0x06C) | user guide section 6 (protection scope) and the register map |

State machines recover through their `when others` branch and the reset. All other logic (registers of the control and data paths, counters, pointers, pipeline registers) relies on the TMR of the synthesis tool. The integrator:

- enables the TMR of the synthesis tool for the system,
- checks in the synthesis report that TMR was applied, that the synchroniser chains of the crossings were not triplicated a second time, and that no register-based storage meant to be protected by TMR was inferred as a RAM primitive,
- requests safe state machines, so that synthesis keeps the `when others` branches (AMD Vivado: property `FSM_SAFE_STATE` = `default_state` on the state registers; Synplify: attribute `syn_encoding` = `safe`),
- protects the configuration memory of SRAM-based FPGAs by scrubbing; this is part of the FPGA design.

The ECC paths of the blocks are verified in simulation by error injection. Whether the protection as a whole meets the requirements of a mission is shown by a radiation test of the system in operation.

## 12. Initialisation by software

Register addresses are byte addresses of the AXI4-Lite port of the block; write registers as 32-bit words and wait for the write response before a read that depends on it.

**`spw0`** (SpaceWire port, `owr_core`) through the top-level ports `spw_reg_S_AxiLite_*`:

1. Read ID (0x00): it reads 0x4F575201.
2. Optionally write LINK_SPEED (0x14) bits 7:0 RUN_DIV: the bit period in the Run state in LinkClk cycles (reset value RunDiv_g); choose it for the far end, which samples at most about LinkClk / 1.2.
3. Write PORT_CTRL (0x10) = 0x34 (RECEIVER_EN, DRIVER_EN, LINK_START) to start the link, or 0x38 (AUTO_START) to wait for the far end.
4. Wait for PORT_STATUS (0x18) bits 2:0 LINK_STATE = 5 (Run) before packets are exchanged.

**`rmap0`** (RMAP node, `omap_core`) through the top-level ports `rmap_reg_S_AxiLite_*`:

1. Read ID (0x000): it reads 0x4F4D4101.
2. None needed: with the default generics the target accepts every command to the logical address 0xFE with the key 0x00 on the whole address space (WinInit_g). A flight configuration narrows the logical addresses (TGT_LA 0x010), the key (TGT_KEY) and the windows (WIN_BASE, WIN_LAST, WIN_CTRL), see the register map.

**`spp0`** (Space Packet node, `spp_core`) through the top-level ports `spp_reg_S_AxiLite_*`:

1. Read ID (0x000): it reads 0x53505001.
2. After the reset wait until TABLE_STATUS (0x040) bits 1:0 (TX_BUSY, RX_BUSY) are 0: the core initialises both APID tables (2048 clock cycles).
3. Nothing else is needed: with TxPathDefault_g and RxPathDefault_g every APID has an enabled path to destination 0 and to receive port 0, destination 0 has the Target Logical Address 0xFE (DEST_CTRL 0x400) and the own address is Tla_g. A flight configuration writes the APID tables (TX_TABLE_APID 0x030 and TX_TABLE_ENTRY 0x034, RX_TABLE_APID 0x038 and RX_TABLE_ENTRY 0x03C) and the destinations (DEST_CTRL 0x400 + 0x20 n).

## 14. Verification

A smoke testbench `spp_over_spw_tb` (VHDL-2008, no extra libraries):

1. Instantiate `spp_over_spw` and drive `Clk_sys` at 100 MHz, `Clk_link` at 200 MHz.
2. Hold `Rst` at '1' for 16 cycles of the slowest clock (100 MHz), then '0'.
3. Keep every external input idle: stream inputs with valid at '0', ready inputs of external outputs at '1', bus requests idle, pins at '0'.
4. Run for at least 100 us (the blocks initialise their tables after the reset) and stop the simulation: it must end without failed assertions, and the handshake outputs of the top level (valid, ready) and the line outputs must not be 'U' or 'X' after the reset. Data outputs may stay undefined while their valid is '0'.
5. Where an AXI4-Lite port is external, read the ID register of the block (section 12) and compare it with the documented value.

With GHDL: analyse the libraries of section 1, then `ghdl -i --std=08 -frelaxed spp_over_spw.vhd spp_over_spw_tb.vhd`, `ghdl -m --std=08 -frelaxed spp_over_spw_tb` and `ghdl -r --std=08 -frelaxed spp_over_spw_tb --stop-time=100us --assert-level=error --ieee-asserts=disable` (`--ieee-asserts=disable` silences the warnings of the numeric package about metavalues before the reset).

Optional end-to-end test, after the initialisation of section 12:

- SpaceWire port (`owr_core`): Loop the SpaceWire line back (Spw_DOut to Spw_DIn, Spw_SOut to Spw_SIn) or connect a second port, start the link and wait for PORT_STATUS LINK_STATE = 5 (Run).
- Space Packet node (`spp_core`): Send one SDU on a send port (APID 0x123, for example) and expect it on receive port 0 with the same APID in user bits 10:0, once the APID tables are ready.
