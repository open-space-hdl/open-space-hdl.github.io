# spacefibre_node: build brief

SpaceFibre node: an OpenFibre port with its AMD Versal GTY adapter carries RMAP on virtual channel 0 (an OpenRMAP target through an N-Char adapter) and Space Packets on virtual channel 1 (OpenSPP, directly on the channel). The assignment of the channels is a convention of this example, not of the cores: any channel carries any packets, and both ends of the link use the same assignment.

This brief was generated by the Open Space Composer from the system file `spacefibre_node.composer.json` (catalog `1b1836436255`).
The file holds the system as edited (`instances`, `connections`, `externals`) and, in `resolved`, the netlist it resolves to.
Build a VHDL-2008 top level `spacefibre_node` from `resolved` as described below; everything needed is in the file and in the listed repositories.

## 3. Architecture

1. Declare every signal of `resolved.signals` (one per port of an instance, named `<instance>_<port>_s`, with the type of the port).
2. Instantiate every entry of `resolved.instances` as `<id> : entity <library>.<entity>`: a generic map with the generics whose `default` is false (the value is the VHDL literal in `vhdl`), and a port map with the `actual` of every port. Leave out the ports with `useDefault` (they keep their VHDL default). Clocks and resets are port actuals on purpose: never assign a clock to another signal.
3. Write every entry of `resolved.nets` as a concurrent assignment `<to> <= <from>;`. They connect the interfaces signal by signal (a packed data word bit by bit), set the side band constants and tie-offs, and connect the top-level ports.

| Clock domain | Frequency | Clock | Reset generator |
| --- | --- | --- | --- |
| System clock (`sys`) | 200 MHz | top-level port `Clk_sys` | `auto_rst_sys` (olo_base_reset_gen, output `auto_rst_sys_RstOut_s`) |
| pa0 Lane clock (`lane`) | 156.25 MHz | output `pa0.LaneClk` (signal `pa0_LaneClk_s`) | `auto_rst_lane` (olo_base_reset_gen, output `auto_rst_lane_RstOut_s`) |

Every block with a synchronous reset gets the output of the reset generator of its clock domain; the generators take `Rst` and release their outputs synchronously to their clocks.

## 5. Constraints

- False path from `Rst`: Asynchronous reset input; the reset generators synchronise its release.
- Maximum delay from the clock of `pa0.LaneClk` to the clock of `Clk_sys`: 5 ns, data path only (`set_max_delay -datapath_only` in Vivado). Clock crossings inside the core (Open Logic): for every pair of its clocks, in both directions, the period of the faster clock.
- Maximum delay from the clock of `Clk_sys` to the clock of `pa0.LaneClk`: 5 ns, data path only (`set_max_delay -datapath_only` in Vivado). Clock crossings inside the core (Open Logic): for every pair of its clocks, in both directions, the period of the faster clock.
- AMD Vivado: source the script of Open Logic once for the scoped constraints of its clock crossings. File `tools/vivado/all_constraints_amd.tcl` of Open Logic.

## 6. Notes from the user guides

**RMAP node** (`omap_core`, `rmap0`): https://openspacehdl.org/openrmap/docs/user_guide.html

- Rst is synchronous and high-active; synchronise its release to Clk, for example with olo_base_reset_gen.
- M_RepData, M_Conf and M_User must be served when connected; a stalled output stalls the received packet stream and the link.
- RMAP address bits above AxiAddrWidth_g must be zero in the windows.
- With AxiMaxBeats_g = 1 and AxiDataWidth_g = 32 the memory master issues single transfers only and can drive an AXI4-Lite slave; tie M_Axi_RLast to '1'.

**N-Char adapter** (`spp_nchar`, `nchar0`): https://openspacehdl.org/openspp/docs/user_guide.html

- A received end of packet marker without data characters is discarded.

**SpaceFibre port** (`ofb_core`, `ofb0`): https://openspacehdl.org/openfibre/docs/user_guide.html

- The VC ports have the link format of OpenSPP: spp_core with DataWidth_g = 32 x NumLanes_g connects to a VC port directly (M_Link_User(0) to S_Vc_TUser); the further user bits of OpenSPP (destination index) do not reach the SpaceFibre port.
- Every VC carries any packets; which VC carries which traffic is a convention of the system that both ends of the link follow.
- Enable the safe implementation of state machines in the synthesis tool (Vivado FSM_SAFE_STATE = default_state on the state registers, Synplify syn_encoding = safe).
- Read ID (0x0FB10007) and GENERICS after the reset; start the link with LANE_CTRL = 0x63 at one end (LaneStart, AutoStart, TxEn, RxEn) and wait for DL_STATUS bits 1:0 = 3 (programming sequence of the user guide).
- All four clocks must run for the reset to complete; CoreClk may be the lane clock (as in the VCK190 reference design).

**SpaceFibre GTY adapter** (`ofb_pa_gty`, `pa0`): https://openspacehdl.org/openfibre/docs/user_guide.html

- Vendor-specific (AMD Versal GTY). hdl/ofb_pa_gty/src/ofb_pa_gty.vhd is not in component_list.txt: add it to the library openfibre, and create the transceiver wizard instance ofb_gtw in the Vivado project with hdl/ofb_pa_gty/tcl/ofb_gtw.tcl (source the file, then ofb_gtw_create ofb_gtw 156.25 for a 156.25 MHz reference clock).
- RefClk is the output O of the IBUFDS_GTE5 of the reference clock pins of the quad; place the buffer in the chip-level top, as hdl/ofb_vck190/src/ofb_vck190_top.vhd does.
- Hold the reset of the core while LaneRst is high; the VCK190 reference design synchronises LaneRst to MgmtClk and ORs it with the power-on reset into Rst of the core.
- The line rate is 6.25 Gbit/s with a 156.25 MHz reference clock, so LaneClk runs at 156.25 MHz.
- Simulation needs the AMD transceiver models (unisim and the simulation files of the wizard); OpenFibre simulates the adapter with tools/run_xsim.py. Without them, the test bench model tb/ofb_tb_pa_model.vhd of OpenFibre (two adapters joined by a lane, one clock) stands in for the adapters of both ends of a link.

**Space Packet node** (`spp_core`, `spp0`): https://openspacehdl.org/openspp/docs/user_guide.html

- Rst is synchronous and high-active; synchronise its release to Clk, for example with olo_base_reset_gen.
- After the reset the core initialises both APID tables (2048 clock cycles); packets are sent and delivered once the tables are ready.
- Serve every receive port, or place a buffer behind a port whose user can stall for long.
- TxBufferBytes_g holds the longest SDU of a port, RxBufferBytes_g the longest Space Packet.
- Hold the side band (TUser) of a send port constant during an SDU.
- The user supplies the packet secondary header at the start of the Octet String and keeps the secondary header flag of an APID static.

## 7. Checks

- Note: ofb0.M_Vc[0] has 1 user bit, nchar0.S_Link 5: bit 0 is connected, bits 4 to 1 are tied to zero at nchar0.S_Link.
- Note: spp0.M_Link has 5 user bits, ofb0.S_Vc[1] 1: bit 0 is connected, bits 4 to 1 are not used.

## 8. Verification

A smoke testbench `spacefibre_node_tb` (VHDL-2008, no extra libraries):

1. Instantiate `spacefibre_node` and drive `Clk_sys` at 200 MHz.
2. Hold `Rst` at '1' for 16 cycles of the slowest clock (200 MHz), then '0'.
3. Keep every external input idle: stream inputs with valid at '0', ready inputs of external outputs at '1', bus requests idle, pins at '0'.
4. Run for at least 100 us (the blocks initialise their tables after the reset) and stop the simulation: it must end without failed assertions, and the handshake outputs of the top level (valid, ready) and the line outputs must not be 'U' or 'X' after the reset. Data outputs may stay undefined while their valid is '0'.
5. Where an AXI4-Lite port is external, read its first register (the identification register of the block, see its user guide) and compare it with the documented value.

With GHDL: analyse the libraries of section 1, then `ghdl -i --std=08 spacefibre_node.vhd spacefibre_node_tb.vhd`, `ghdl -m --std=08 spacefibre_node_tb` and `ghdl -r --std=08 spacefibre_node_tb --stop-time=100us --assert-level=error`.

Vendor-specific blocks need the simulation libraries of their vendor: `pa0` (ofb_pa_gty, AMD Versal GTY); see their notes in section 6.
