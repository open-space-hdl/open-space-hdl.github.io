## 3. Architecture

1. Context clause (`resolved.context`): `library ieee;` `use ieee.std_logic_1164.all;`
2. Declare every signal of `resolved.signals` (one per port of an instance, named `<instance>_<port>_s`, with the type of the port).
3. Instantiate every entry of `resolved.instances` as `i_<id> : entity <library>.<entity>`: a generic map with every generic (the value is the VHDL literal in `vhdl`, package constants fully qualified; write the defaults too, where `default` is true, so that a new default of a core cannot change the system unnoticed), and a port map with the `actual` of every port. Leave out the ports with `useDefault` (they keep their VHDL `default`). Clocks and resets are port actuals on purpose: never assign a clock to another signal.
4. Write every entry of `resolved.nets` as a concurrent assignment `<to> <= <from>;`. They connect the interfaces signal by signal (a packed data word bit by bit), set the side band constants and tie-offs, and connect the top-level ports.

## 4. Clocks and resets

| Clock domain | Frequency | Clock | Reset generator |
| --- | --- | --- | --- |
| System clock (`sys`) | 100 MHz | top-level port `Clk_sys` | none: no block of the domain has a synchronous reset |
| Link clock (`link`) | 200 MHz | top-level port `Clk_link` | none: no block of the domain has a synchronous reset |

Reset ports (`reset` of the port):

| Port | Reset | Actual | Why |
| --- | --- | --- | --- |
| `rmap_node0.Rst` | asynchronous | `Rst` | Unsynchronised reset of the parent (its Rst); rmap_node synchronises its release in every clock domain with its own reset generators. |
| `rmap_node1.Rst` | asynchronous | `Rst` | Unsynchronised reset of the parent (its Rst); rmap_node synchronises its release in every clock domain with its own reset generators. |

`Rst` is the asynchronous system reset. A reset generator asserts the reset of its domain at once and releases it synchronously to the clock; a block with an asynchronous reset synchronises the release itself.

## 5. Constraints

Every clock crossing is an Open Logic block. Between the clocks of a crossing a maximum delay applies in both directions, the period of the faster clock, data path only (Open Logic clock crossing principles). Do not declare these clocks as asynchronous clock groups: in Vivado `set_clock_groups -asynchronous` overrides the delay limits.

- False path from `Rst`: Asynchronous reset input; the reset generators synchronise its release.
- False path from `rmap_node0_spw_port0_spw0_Spw_DIn`, `rmap_node0_spw_port0_spw0_Spw_SIn`: Inputs that rmap_node synchronises inside.
- Output registers in the I/O blocks for `rmap_node0_spw_port0_spw0_Spw_DOut`, `rmap_node0_spw_port0_spw0_Spw_SOut`: Place the output flip-flops of data and strobe in the I/O blocks with matched routing.
- False path from `rmap_node1_spw_port0_spw0_Spw_DIn`, `rmap_node1_spw_port0_spw0_Spw_SIn`: Inputs that rmap_node synchronises inside.
- Output registers in the I/O blocks for `rmap_node1_spw_port0_spw0_Spw_DOut`, `rmap_node1_spw_port0_spw0_Spw_SOut`: Place the output flip-flops of data and strobe in the I/O blocks with matched routing.

## 6. Throughput

The capacity of every path from a source (an external stream input, the inbound side of a link) to a sink (an external stream output, the outbound side of a link), from the rate data of the catalog: every element at its packet length and at the frequency of its clock domain, the path at its slowest element (in bold). Capacities are payload rates at the source in bit/s (SI prefixes, three significant digits). The packet lengths are reference points, not stated traffic, unless the system states traffic for the interface.

No path from a source to a sink carries rate data.

Blocks without rate data end the paths through them:

- `omap_core` (`rmap_node0/rmap0`, `rmap_node1/rmap0`).

## 7. Packet sizes and buffers

The largest packet at every interface with a size limit, from the size data of the catalog: the largest packet a source states, the chunks of a route, the bytes the routes add. A source that states no largest packet, or a link, is not bounded: it meets the limit of the first interface that has one. A limit that is only the reset value of a register is marked: software can change it.

No interface with a size limit receives packets.

Blocks without a length limit:

- `owr_core` (`rmap_node0/spw_port0/spw0`, `rmap_node1/spw_port0/spw0`): no length limit, tested up to 1000 B.

Blocks that publish no length limit (packets through them are checked against the other blocks only):

- `omap_core` (`rmap_node0/rmap0`, `rmap_node1/rmap0`).

## 8. Notes from the user guides

**SpaceWire port** (`owr_core`, `spw_port/spw0`): https://openspacehdl.org/openwire/docs/user_guide.html

- LVDS output buffers for data and strobe and LVDS input buffers with fail-safe biasing belong to the top level; the core contains no I/O buffer.
- Enable the safe implementation of state machines in the synthesis tool.
- Set INT_HOLDOFF and INT_ACK_DELAY for the network before distributed interrupts are used.
- Serve the indication ports before the indication FIFO (16 entries) fills.
- Write registers as 32-bit words; a read that depends on a write waits for the write response.

**RMAP node** (`omap_core`, `rmap_node/rmap0`): https://openspacehdl.org/openrmap/docs/user_guide.html

- Rst is synchronous and high-active; synchronise its release to Clk, for example with olo_base_reset_gen.
- M_RepData, M_Conf and M_User must be served when connected; a stalled output stalls the received packet stream and the link.
- RMAP address bits above AxiAddrWidth_g must be zero in the windows.
- With AxiMaxBeats_g = 1 and AxiDataWidth_g = 32 the memory master issues single transfers only and can drive an AXI4-Lite slave; tie M_Axi_RLast to '1'. Known defect of Open Logic olo_axi_master_simple up to 4.7.0-ft.4 (fix pending in open-logic-ft): with AxiMaxBeats_g < AxiDataWidth_g/8, commands that the memory master splits into several AXI transactions read or write the first word repeatedly, with status 0.

## 9. Initialisation by software

Register addresses are byte addresses of the AXI4-Lite port of the block; write registers as 32-bit words and wait for the write response before a read that depends on it.

**`spw_port/spw0`** (SpaceWire port, `owr_core`, in every instance of the subsystem `spw_port`) through the ports `reg_S_AxiLite_*` of `spw_port`:

1. Read ID (0x00): it reads 0x4F575201.
2. Optionally write LINK_SPEED (0x14) bits 7:0 RUN_DIV: the bit period in the Run state in LinkClk cycles (reset value RunDiv_g); choose it for the far end, which samples at most about LinkClk / 1.2.
3. Write PORT_CTRL (0x10) = 0x34 (RECEIVER_EN, DRIVER_EN, LINK_START) to start the link, or 0x38 (AUTO_START) to wait for the far end.
4. Wait for PORT_STATUS (0x18) bits 2:0 LINK_STATE = 5 (Run) before packets are exchanged.

**`rmap_node/rmap0`** (RMAP node, `omap_core`, in every instance of the subsystem `rmap_node`) through the ports `rmap_reg_S_AxiLite_*` of `rmap_node`:

1. Read ID (0x000): it reads 0x4F4D4101.
2. None needed: with the default generics the target accepts every command to the logical address 0xFE with the key 0x00 on the whole address space (WinInit_g). A flight configuration narrows the logical addresses (TGT_LA 0x010), the key (TGT_KEY) and the windows (WIN_BASE, WIN_LAST, WIN_CTRL), see the register map.

## 11. Verification

A smoke testbench `dual_rmap_node_tb` (VHDL-2008, no extra libraries):

1. Instantiate `dual_rmap_node` and drive `Clk_sys` at 100 MHz, `Clk_link` at 200 MHz.
2. Hold `Rst` at '1' for 16 cycles of the slowest clock (100 MHz), then '0'.
3. Keep every external input idle: stream inputs with valid at '0', ready inputs of external outputs at '1', bus requests idle, pins at '0'.
4. Run for at least 100 us (the blocks initialise their tables after the reset) and stop the simulation: it must end without failed assertions, and the handshake outputs of the top level (valid, ready) and the line outputs must not be 'U' or 'X' after the reset. Data outputs may stay undefined while their valid is '0'.
5. Where an AXI4-Lite port is external, read the ID register of the block (section 9) and compare it with the documented value.

With GHDL: analyse the libraries of section 1, then `ghdl -i --std=08 -frelaxed dual_rmap_node.vhd dual_rmap_node_tb.vhd`, `ghdl -m --std=08 -frelaxed dual_rmap_node_tb` and `ghdl -r --std=08 -frelaxed dual_rmap_node_tb --stop-time=100us --assert-level=error --ieee-asserts=disable` (`--ieee-asserts=disable` silences the warnings of the numeric package about metavalues before the reset).

Optional end-to-end test, after the initialisation of section 9:

- SpaceWire port (`owr_core`): Loop the SpaceWire line back (Spw_DOut to Spw_DIn, Spw_SOut to Spw_SIn) or connect a second port, start the link and wait for PORT_STATUS LINK_STATE = 5 (Run).
