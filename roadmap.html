In progress

Hardware tests for TRL 4

The cores are at TRL 3: fully verified by simulation. TRL 4 needs synthesis and timing closure on a target FPGA and a hardware test in the laboratory, with a test plan and a test report.

The first system in hardware is a SpaceFibre node with RMAP control and AES-GCM encryption of Space Packets on an AMD Versal evaluation board. It covers four cores:

CoreRole in the system
OpenFibreThe SpaceFibre port with its transceiver adapter
OpenRMAPThe RMAP target through which the far end of the link controls the system
OpenSPPThe Space Packets on a virtual channel of the link
OpenCryptoThe AES-GCM encryption of the packets

OpenWire and OpenCompact follow with their own hardware runs.

CCSDS space link core

The first new core implements the space data link with its synchronisation, channel coding and security. It completes the on-board chain from the instrument to the transmitter:

  1. Instrument
  2. Compression OpenCompact
  3. Encryption OpenCrypto
  4. Space Packets OpenSPP
  5. Transfer frames space link core
  6. Transmitter

The core grows in phases:

New Open Logic building blocks

The space link core, later cores and the systems built from them need general-purpose functions that belong in a VHDL library rather than in one core. They are developed in Open Logic FT first and then proposed to Open Logic. The first three are prerequisites of phase 1 of the space link core and come with it. The CAN controller is done; the others follow with the cores and systems that use them.

Building blockPurposeState
Galois field packageArithmetic in GF(2m) for any field polynomial: the common base of Reed-Solomon and BCH codesNext
Reed-Solomon encoder and decoderStreaming codecs for configurable codes, shortened codes and interleaving; the decoder reports the corrected symbols and uncorrectable codewordsNext
Convolutional encoderConfigurable constraint length, polynomials and puncturingNext
Sync word detectorFinds a sync word in a bit stream despite a configurable number of bit errorsPlanned
Symbol ECC for external memoriesA single-symbol-correcting, double-symbol-detecting option of the ECC codecs, for external memories such as DDR and FlashPlanned
AXI4 decoder with burst accessAXI4 bursts in; per port passed through to AXI4 memories or split into single accesses for AXI4-Lite register banks, so that one decoder serves memories and registers. First an AXI4-to-AXI4-Lite converter in front of the existing AXI4-Lite decoderPlanned
CAN 2.0 controllerThe CAN data link layer with messages in and out as streams (olo_intf_can), the base of the CAN core belowDone

Planned

Reference systems and evaluation boards

A reference system is a complete FPGA design built from the cores for a test in the laboratory. After the SpaceFibre node with encryption above, the second reference system adds CCSDS 123.0-B-2 image compression with OpenCompact in front of the encryption.

Further evaluation boards follow the AMD Versal board, in this order:

  1. Microchip PolarFire
  2. Microchip RTG4
  3. AMD Versal AI Edge Series Gen 2

The Microchip boards will show the vendor independence of the cores on space FPGA families. Each board family needs its own physical adapter of OpenFibre for its transceivers.

Planned

Composer

Once the catalog of the Composer has a memory block, the Composer connects an RMAP target directly to its AXI4 port with bursts. Systems that move bulk data by RMAP into memory with a high latency, such as DDR, then reach the burst rates. Register banks stay on the AXI4-Lite decoder, where one beat per access costs little. With the AXI4 decoder, the RMAP target keeps its bursts in every system.
