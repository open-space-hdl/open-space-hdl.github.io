Open Space Composer · Beta

Composer file format

The Composer saves one system per file with the extension .composer.json. The file holds the system as it was edited and, derived from it, the netlist of the VHDL top level, the results of the checks and a build brief in Markdown. A person or an AI agent can build the top level from the file and the pinned source repositories alone.

Format version 1. JSON schema: /composer/schema/system-1.json. Examples: the example systems of the Composer, for instance encrypted-spp-over-spw.composer.json.

The editor reads the edited parts and resolves the system again; the derived parts are written for readers of the file. When the stored netlist differs from the system it describes, the editor reports it and writes the new netlist on the next save. A file saved with another version of the catalog opens with a remark.

The system as edited

An instance names a catalog block (<source>/<entity>), optionally a preset, the generics that differ from the catalog and the preset, and the clock domain of every clock input. An interface is named <instance>.<Interface>; an element of a vector interface carries its index, for example spp0.S_Tx[1]. 

"instances": [
  { "id": "frm0", "block": "opencrypto/ocr_framer", "generics": {}, "clocks": { "Clk": "sys" },
    "constants": { "Cfg": { "slot": 2 } } },
  { "id": "ocr0", "block": "opencrypto/ocr_core", "generics": { "DenseOutput_g": true }, "clocks": { "Clk": "sys" } }
],
"connections": [
  { "id": "c3", "from": "ocr0.M_Out", "to": "spp0.S_Tx[0]",
    "sideband": { "apid": 291, "shi": false, "type": false, "nameValid": false, "name": 0 } }
],
"externals": [ { "interface": "frm0.S_In", "prefix": "pkt_" } ]
  • sideband: constants of a receiving interface whose side band the driver does not provide, for example the APID of a send port of OpenSPP.
  • constants: values of an unconnected interface whose inputs are constants of the instance, for example the key slot of the OpenCrypto framer.
  • adapters: settings of the blocks the Composer inserts on a connection, for example the depth of an asynchronous FIFO: { "cdc": { "Depth_g": 64 } }.
  • Values of generics: booleans and numbers as JSON, std_logic as "0" or "1", vectors as VHDL literals ("x\"FE\""), strings without quotes.

The resolved netlist

resolved describes the top level completely. It contains the placed blocks and the blocks the Composer inserts: width converters, clock crossings (asynchronous FIFOs with the side band packed into the data word) and one reset generator per clock domain. Writing the top level takes three steps:

  1. Declare a signal for every entry of signals. Every port of an instance with a signal actual has one, named <instance>_<port>_s, with the VHDL type of the port.
  2. Instantiate every entry of instances as <id> : entity <library>.<entity>. The generic map holds the generics whose default is false, with the VHDL literal in vhdl. The port map holds the actual of every port: its signal, a clock, a reset or open; a port with useDefault is left out.
  3. Write every entry of nets as the concurrent assignment to <= from;.
signal spw0_M_Pkt_TData_s : std_logic_vector(7 downto 0);
...
rmap0 : entity openrmap.omap_core
    generic map (Initiator_g => false)
    port map (Clk => Clk_sys, Rst => auto_rst_sys_RstOut_s, S_Pkt_TData => rmap0_S_Pkt_TData_s, ...);
...
rmap0_S_Pkt_TData_s <= spw0_M_Pkt_TData_s;
auto_cdc_c5_In_Data_s(36) <= nchar0_M_Link_Last_s;
spp0_S_Tx_User_s <= "0000000000000000000100100011";
EntryMeaning
entity, portsName and ports of the top-level entity, in order. Rst is the asynchronous system reset (high-active), Clk_<domain> the clock of an external clock domain, the other ports belong to external interfaces and are named <prefix><port> (an element of a vector interface adds _<index>).
instancesEntity, library, origin (placed or inserted, with the reason), clock domain, every generic with its value, VHDL literal and whether it is the default, every port with its type and actual.
signalsSignal declarations of the architecture.
netsAssignments: connections signal by signal (kind connection), constants of side bands and missing signals (constant), tie-offs of unconnected inputs (tie-off) and the top-level ports (top). A packed data word appears bit field by bit field.
packingBit fields of every packed data word, for example data 31:0, keep 35:32, last 36, user 37.
clocks, resetsClock domains with frequency and the actual of their clock inputs; the reset generator of every domain and the signal of its synchronous reset.
constraintsAsynchronous clock groups, false paths, I/O registers and the scoped constraint script of Open Logic, in terms of the top level.
compileVHDL libraries in compile order with repository, commit or tag, file list and its format, and the entities used. files: one VHDL file per line in compile order; modules: one module directory per line, with the sources in <module>/src/*.vhd, packages first.
problemsInconsistencies found while building the netlist; empty for a correct catalog.

Clocks and resets are port actuals and never assignments, so that no clock gets a delta delay in a simulation. One olo library (Open Logic FT) serves all blocks of the system.

Checks

checks lists the results of the structural checks (missing connections of interfaces that must be served, side band constants, widths, clock crossings) and of the design rules of the catalog (clock relations, generics that depend on each other, buffer sizes of a chain). Each entry has a severity (error, warning, info), the rule and a message, and names the instance, connection or clock domain it is about. A system with an error is not ready to build.

The build brief

agent.brief is a Markdown text for a person or an AI agent: the repositories and their compile order, the ports of the top level, how to write the architecture from resolved, the clock domains and resets, the constraints, the notes of the user guides of the blocks, the open checks and a smoke test bench to verify the result with GHDL.

Versions and the catalog

The block catalog of the Composer is checked against the VHDL entities of the cores at their pinned commits. generator.catalog and resolved.catalog name the catalog a file was resolved with; a newer catalog may resolve the same system differently (for example after a core update), and the editor says so when it opens the file.
